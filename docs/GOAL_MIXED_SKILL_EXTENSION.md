# Raw skill extension in one continuing goal controller

`cpp/apps/goal_mixed_skill_extension.h` supplies explicit raw bootstrap lessons and independently scored query environments. It operates on the existing `GoalControlledRelationalSession`; successful stages do not replace its knowledge, policy, credits or RNG. This is a bounded integration component for the continuing mixed curriculum, not an autonomous acquisition result.

Call `mixed_skill::configure_initial(learner)` once, after any initial capacity setup and before every raw lesson. It enables disjunctive concepts with body bound three and two clauses, then composed learning with 5,000 proposals, interleave quantum 100 and the repair bank. Body three preserves the route library's compositional six- and nine-edge meanings. These are declared representational/search settings, not seeded task programs.

At a mission boundary with learning enabled and rebuilt knowledge:

- `teach_initial(learner, output, prefix)` supplies the 11 raw primitive outcomes and 25 computational language examples used by the successive-repair fixture. They establish short follow/count/equality programs without supplying compiled definitions or weights.
- `extend(learner, output, prefix)` supplies 21 duplicate-count counterexamples, ten longer-follow counterexamples, then four positive/negative red-or-blue concept examples and their language labels. It rebuilds between the count and follow stages to exercise successive repair.
- `revise_follow_support(learner, output, expected_version, active, prefix)` withdraws or restores only the extension's ten raw follow-language supports. It does not revise a mission outcome or independently verified motor receipt.

Each operation stages its evidence output and retains a complete knowledge backup for failure rollback. The focused test triggers a stale version on the tenth revision after nine provisional changes and verifies restored receipt versions, activity, model version, primitive weights, controller weights, update count, credit count and empty output. A failing external stream can itself contain a partial write; the session still rolls back, and that output is not a committed record.

`QueryEnvironment(Kind, size, other, copies, depth, offset)` implements the existing harness `Environment`. Kinds are `equal_counts`, `numeric_count`, `follow_endpoint` and `union_query`. It creates one complete public query world with no afforded motors. The independent outcome evaluator parses public text and uses set cardinality, a unique-successor walk, or direct red/blue membership. It never selects truth by a private goal ID or invokes the learned evaluator. Fresh entity names are controlled by `offset`; union `size` is a two-bit red/blue mask. Follow `other` is zero for an absent endpoint and one for the actual endpoint. Counts vary `size` and `other` independently.

The controller's mission limits require a positive motor cap even though these environments afford no motors. Use one root, zero derived goals, 64 decisions and a positive cap such as 32. Actual query motors remain zero. The shared public observation/menu demonstration can guide initial reason/finish examples; the helper supplies no policy action labels or parameter assignments. Raw semantic lessons, backpropagated controller demonstrations and reward credit remain separately logged mechanisms in the same learner.

To introduce repairs in a later phase, early query missions must use single-copy counts and follow depth zero or one. Otherwise their ordinary verified terminal feedback can already supply repair counterexamples. The later raw extension should occur after existing controller credits, followed by continued mixed missions. A fresh query has no new text semantics unless the relevant raw language examples have been taught.

`cpp/tests/test_goal_mixed_skill_extension.cpp` checks initial wrong answers on duplicate counts and long follow, repairs from raw counterexamples, 36 renamed/fresh probes, actual owned query callbacks, nonzero controller history surviving extension, withdrawal/restoration of exact combined primitive weights, and six-/nine-edge meanings plus generic long-goal proposals. Frozen sources and optimized/sanitizer commands are recorded by `python/validate_goal_mixed_skill.py` under `logs/goal_mixed_skill_extension_v1`. That record covers the declared bounds and seed, not arbitrary new skills, scheduler acquisition, or the full Organism interface.
