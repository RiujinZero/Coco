# Native text-to-procedure integration

The learned reasoning procedures can answer through Coco's native byte-generation
path. The remaining failure in this experiment is language grounding: new wording
does not automatically acquire the meaning of a known question or fact.

This follows [the composition experiment](REASONING_COMPOSITION_EXPERIMENT.md).
It tests an experimental bridge, explicitly attached to `Organism`; it does not
enable a new default chat model or establish general language understanding.

## What runs

The inference route is:

```text
observed USER bytes
    -> grounded sentence frames -> episode facts and entity bindings
    -> normalized question form -> learned procedure
    -> callable learned skills -> typed returned value
    -> answer bytes -> SequenceMemory competition -> Organism distribution
    -> commit_outcome(self=true)
```

`SequenceMemory::capture` passes observed bytes and their provenance to an optional
`LanguageReasoner`. At `ASSISTANT:` the reader binds the question's entity mentions,
looks up its learned procedure, and executes it. The result is rendered as an
entity name, `yes`/`no`, or decimal digits. During generation, the normal sequence
arbitration path supplies those bytes to the organism's distribution and cancels
unrelated sequence replay. The probe chooses bytes from that distribution and
commits each generated byte through `Organism::commit_outcome`.

The probe does not substitute a structured answer for the organism's output. Its
scorer receives the generated reply only after generation has finished. Inference
receives the raw story and question, without task IDs, gold triples, answers,
supporting-fact indices, or a program graph.
Half the test prompts include the space after `ASSISTANT:`; half end at the colon.

## Learning and supplied structure

There are three distinct learning stages; their supervision is deliberately
visible:

1. **Primitive skills:** the previously tested native sparse-expansion and local
   consequence-route learner is bootstrapped from short action demonstrations.
   The weights are frozen before language training and evaluation.
2. **Fact reading:** aligned training sentences supply subject, relation identity,
   and object. The reader replaces grounded spans with argument slots and retains
   the intervening words. At least two distinct grounded pairs must support a
   frame. Initially this learns four sentence frames: two surface forms each for
   a functional link and an item-holding relation, including reversed surface
   argument order. This is supervised symbolic frame induction, not raw-text-only
   discovery of semantics.
3. **Question procedures:** entity mentions are replaced with ordered argument
   slots. The remaining token sequence is an opaque question-form key. Twelve
   verified answers on different worlds teach a program for each wording through
   bounded search over the learned skills. No task label or composite action trace
   is supplied to this stage. The learner discovers 14 procedures initially:
   two wordings for each of seven task families.

The bridge fixes word segmentation, case normalization, two grounded relation
handles, two argument registers, reply formatting, and the chat role protocol.
These are provided interfaces. The skill policies, fact-frame mappings and
question-to-program mappings are learned. The question reader is exact over its
normalized token sequence; it has no paraphrase model. This input grammar uses
punctuation-delimited statements and a question ending in `?` inside the
`USER:` / `ASSISTANT:` protocol.

## Held-out protocol and results

Three fixed seeds are evaluated. Each seed trains on 168 answered dialogues.
Training paths have 1–3 links and target counts are 0–3. Tests use paths of
4, 8, 12 or 32 links and target counts of 4–24, with fresh entity names,
shuffled facts, duplicate item assertions and unrelated facts. Source and endpoint
holdings are independent; follow-then-count cases explicitly have different
counts, preventing a shortcut that counts before following the path.

Entity names in the main arm use alphabetic characters with random prefixes, so
the comparison does not depend on defeating the old reader's alphabetic tokenizer
or deliberately colliding its three-letter stem hashes. A separate arm tests
identities containing digits.

| Condition | Procedure-owned correct replies | Meaning |
|---|---:|---|
| Learned wording, new worlds | 2,100 / 2,100 | Complete native text-to-byte path |
| Learned wording, alphanumeric identities | 420 / 420 | Entity identity and numeric output survive byte handling |
| Unseen question wording, before teaching | 0 / 840 | Facts are all extracted; no question procedure is selected |
| Unseen fact wording, before teaching | 0 / 840 | Reader refuses an incomplete fact representation |
| New fact frames taught on separate training worlds | 840 / 840 | Existing question procedures work immediately |
| New question wording taught with 12 answers per form | 840 / 840 | New procedures work on the unchanged held-out worlds |
| Both kinds of adaptation, all test groups | 4,200 / 4,200 | Previously learned forms also retain their accuracy |

The two adaptation interventions address separate components. Teaching the new
fact frames does not improve coverage of unseen question wording. Teaching the new
question forms does. Adaptation uses 84 additional training dialogues per seed;
their entities and worlds are disjoint from the held-out cases. The held-out set
is reused to measure before/after behavior, and never supplies training answers.

**Binding ablation:** without SAVE/SWAP, the two-result compositions—comparing
counts, comparing endpoint counts and comparing endpoints—produce no successful
procedure-owned answers on 900 tests. The four other families retain 1,200/1,200
accuracy. Reading and argument interpretation remain correct. This reproduces the
composition boundary inside the native text path.

The existing learned chain reader is also run through the same native organism
on the alphabetic-name arm. Its exact-match total is retained in
`logs/reasoning_language_audit.json` under `chain_baseline/known`. This is a
descriptive integration baseline: it receives the same answered dialogue stream,
but does not receive the new reader's aligned fact supervision. It is not an
equal-supervision comparison between learning algorithms.

When the procedure module declines to answer, the existing byte generator remains
available and occasionally guesses correctly. `covered=0` means that the procedure
module did not own the reply; it does **not** mean the whole chat system emitted
an abstention. Raw exact-match counts, including such guesses, are preserved in
the JSON results. The table above separates verified procedure output from them.

## Native wiring and verification

- `cpp/include/laminar/reasoning_language.h`: learned fact frames, question-form
  binding, explicit verified feedback, episode state, typed answer serialization.
- `cpp/include/laminar/sequence.h`: optional capture and answer-competition hooks.
- `cpp/include/laminar/organism.h`: explicit `attach_reasoner` interface.
- `cpp/apps/reasoning_language_probe.cpp`: raw-byte native experiment and ablations.
- `python/reasoning_language_probe.py`: separate training, adaptation and test worlds.
- `python/check_reasoning_language.py`: independent label computation from triples,
  disjoint-entity checks, per-seed result assertions and evidence hashes.
- `cpp/tests/test_reasoning_language.cpp`: provenance, reset, ambiguity, incomplete
  reading, explicit feedback, numeric emission and ownership-release contracts.

The probe asserts that skill weights, procedures, question mappings and verified
evidence counts remain unchanged during each evaluation phase. The independent
audit recomputes every corpus answer from its fact graph. AddressSanitizer and
UndefinedBehaviorSanitizer pass the boundary tests; the existing kernel/address
tests pass as well.

The native organism uses a small 128-slot configuration with body and structural
training disabled to isolate the integration. Its existing sequence machinery
still processes the text. These results do not measure training a full 200,000-unit
population or a throughput improvement. Default application behavior is unchanged
unless a caller explicitly attaches the experimental reader.

## What this establishes and what is next

The earlier successful procedure mechanism survives contact with the real native
input/output path. The missing bridge can be built without coding a solver for
each composite question. Bound skill calls, retained results, verified procedure
memory and an answer-emission interface are sufficient for this controlled domain.

The next useful work is **learning reusable language meanings**. The current
whole-question key treats a paraphrase as a new task and repeats program search.
A stronger language interface would learn shared relation and question fragments,
bind their arguments, and reuse the already learned operations. It should be tested
on held-out wording and combinations, with extraction, interpretation and execution
reported separately as here.

This prototype assumes static, complete, functional-link worlds and distinct-item
counting. It does not establish temporal updates or retractions, pronoun or
multiword-entity resolution, negation, ambiguous links, contradictory facts,
open-world counts, durable model persistence, or general bAbI/free-form chat
transfer. Unsupported surface facts invalidate the episode, but semantically
contradictory facts in otherwise recognized frames are outside the tested contract.
Production arbitration also needs to distinguish a grounded procedure answer from
an unverified fallback continuation.

## Reproduction

The skill corpus comes from the preceding composition experiment. From the root:

```sh
python python/reasoning_language_probe.py
bash scripts/reasoning_language.sh
python python/check_reasoning_language.py
```

On Windows use `wsl -d Ubuntu -- bash scripts/reasoning_language.sh`.
Results are `logs/reasoning_language_native/0.json` through `2.json`; example
replies and selected programs are in adjacent `.examples.txt` files.
`logs/reasoning_language_audit.json` records totals and source/corpus/result hashes.
