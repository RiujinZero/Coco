# Explicit stopping examples: bounded declaration

The final shared version 3 setup uses one public demonstration function, the
raw long/short-procedure semantic bootstrap, and a common sixteen-candidate
derived-goal capacity with paid-exhaustion observation enabled. Its finite
environment smoke passes 14/14 training fixtures, 14/14 held-out fixtures and
2/2 long examples without fitting a policy. Earlier variants below are retained
as experimental history; the final setup and evidence are summarized at the end.

This generator supplies examples for the user-requested stopping curriculum.
It uses the existing seven-action controller and the raw learned `inspect`,
`route`, and `span` language library. It neither changes production termination
nor installs policy weights, concept definitions or procedures. A mission ends
through an actual learner `finish` operation and verified outcome callbacks, or
the existing 256-decision limit. Correct physical satisfaction alone never ends
it. Any future direct fitting of source-tagged examples is a separately declared
training operation owned by the continuing learner.

The public example function receives only the existing 32 observation floats
and legal operation menu. It activates an inspected root, yields when another
public root arrives, reasons when uncached (including partial views), retrieves
an unresolved partial view, finishes
a known true/false query or satisfied physical request, and continues an
incomplete physical task with its learned plan or paid search. Its source tag is
`stopping_curriculum_v1`. The evaluator's private graph truth is used solely for
final labels. Public request IDs never select an expected answer or operation.

The fixed version 1 inventory contains fourteen training and fourteen held-out
specifications. Training includes true/false one- and three-edge queries;
already-complete three-/six-edge physical requests; one, two or three missing
edges; partial true/false queries and a partial physical request; and urgent
same-world queries arriving during six-edge physical work at ticks 3/5.
Held-out cases use fresh bindings, new action-order seeds, a disconnected fork
instead of a distractor chain, true/false six-edge query contexts, already-done
one-/six-edge physical worlds, four/five missing edges and a middle missing edge,
partial three-/six-edge queries and a partial six-edge physical request, and
urgent arrivals at unseen ticks 4/6. Thus both sets contain states requiring
`finish` and states requiring continued work or observation. This is a finite
fixture holdout, not a generalization claim beyond these structures.

Every physical affordance has ordinary public adjacency metadata, including
distractors. Physics adds one edge per acknowledged action. Labels are computed
by independent exact-length graph traversal of the actual world. All meanings
come from the existing raw semantic lessons; no new operation is added.

The generic harness calls `read()` when posting a request, overriding its stored
visible field. Partial cases therefore declare an explicit disclosure schedule:
the first read used for the public offer returns an incomplete view with edge
facts withheld; the next requested read returns the complete actual scene at a
new observation revision. Partial cases have one root, so an arrival cannot
consume that reveal. A physical callback also exposes the actual resulting
complete world. The private outcome computation never calls `read()`.

The initial stopping-only declaration used at most two roots, zero derived candidates, 256 decisions,
32 motors and the existing success-first zero prices, retaining raw counters.
Urgent slack is sixteen decisions. Interrupt cases begin with six absent edges,
so their ticks 3/5 or 4/6 precede the earliest correct nine-decision completion.
The bounded initial smoke may route explicit example hints with
`finish_mission(0)` to verify the environment, read schedule and demonstration
contract. It must assert unchanged policy weights and zero policy updates.
No autonomous training campaign is part of this implementation task.

The mixed continuing bootstrap uses the opt-in paid-search-exhaustion
observation contract in every family, so feature 15 has one consistent agenda
meaning. `long_task::demonstration` supplies the separately source-tagged generic
long-goal examples using only public progress, plan, deadline and paid-exhaustion
features. It prefers a valid positive-progress derived candidate over an
irrelevant zero-progress one, retries smaller exhausted allowances and skips a
genuinely exhausted global allowance. This helper is for explicit warm examples;
the autonomous learner must make its own choices after guidance ends. Raw long
meaning and short procedure acquisition still use the existing evidence helper.

Before any fitting, the two family wrappers were unified behind
`curriculum_demonstration` in `goal_curriculum_demonstration.h`, with source
`continuing_curriculum_v1`. Identical observation/menu pairs therefore receive
identical labels regardless of the environment family. Positive partial reader
queries reason and can finish from known positive evidence without repeatedly
requesting a complete world. Unresolved partial queries retrieve and reason
again. Complete physical roots pay an initial agenda reason; a root that exceeds
that first allowance can activate the ordinary physical controller and continue
its bounded search. Derived choices require paid positive progress, with the
declared global-exhaustion skip. The finite smoke checks both wrappers against
the common function on every visited state and supplies no family ID to it.

The first unified-helper smoke passed all 28 stopping cases but failed its two
long examples: activating a root made the old equal-deadline check skip all
derived children while its active plan was unavailable. Those results remain
under `logs/goal_curriculum_smoke_v1`. A separately declared helper revision
permits considering derived candidates with equal inherited deadlines when the
active plan is publicly unavailable (observation 28). It retains deadline
priority otherwise, and still requires positive paid progress before activating
a derived candidate. This is a correction to the shared example policy before
any fitting, with no family ID or private usefulness condition.

The version 2 helper made long physical completion feasible but answered both
urgent queries late. Its extra active-root search changed the scheduling context.
The version 3 mixed setup instead uses one warmed semantic library and the
already-authorized raw short-route procedure acquisition before examples, with
the same sixteen-derived-candidate, minimum-two-atom capacity in every physical
family. The common helper returns to the proven long agenda rule: activate a
root only once satisfied or planned, otherwise consider generic derived work.
Three-edge stopping roots can reuse the acquired three-action procedure; longer
roots can use the same generic proposals as the nine-edge task. This avoids
family-specific root activation and preserves public deadline priority. The
version 3 smoke applies the existing raw long-extension helper before all cases;
this is semantic/evaluator setup, with no policy fitting. Earlier zero-derived
stopping-only and late-urgent long results remain preserved in their own logs.

The authoritative version 3 result is 14/14 training-environment references,
14/14 held-out-environment references and 2/2 long references. The long cases
finish in 120/110 decisions with nine motors each, correct urgent deadlines and
actual interruption/resumption. Every partial stopping fixture performs one
read after first reasoning to Unknown. The separate positive-partial observation
check reasons first and then finishes a known True answer without a forced read.
Every visited state gives the same label through both family wrappers. These
are explicit-hint environment checks with zero policy updates and unchanged
weights, not an autonomous held-out generalization score. The actual mixed
continuing learner campaign is separately owned and declared.

`logs/goal_curriculum_smoke_v3/source` and `source_manifest.json` freeze the
tested code; `smoke_summary.json` and `smoke_trace.jsonl` retain results and
complete public observations/menus. `GOAL_STOPPING_CURRICULUM_VALIDATION.json`
records source/binary hashes and the earlier failed variants. The optimized
bounded smoke passed; no additional training or sanitizer campaign was run for
this environment-only addition.
