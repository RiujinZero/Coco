# A grounded session on the trainer's byte path — 2026-09-23

The question reader, report journal and learned correction constructions now run
as one optional byte-stream session. The host does not label each user turn as a
question, correction or clarification. Learned interpretations determine the
route; ordinary questions and corrections share the same evidence history.
`laminar_train` can install this session with `grounded_bootstrap=PATHS`.

This connects previously separate experimental calls to a reusable runtime and
the standard trainer. The tested symbolic meanings are pretrained and remain
frozen during stream ingestion. It does not yet teach those meanings jointly
with the neural body from ordinary mixed-stream dialogue.

## Runtime and source protocol

`cpp/include/laminar/grounded_session.h` receives each committed byte through an
optional observer in `SequenceMemory`. `Organism::attach_grounded_observer`
installs the reader used for output and its observer together. Direct
`attach_reasoner` clears the observer and retains the preceding standalone path.
Without either attachment, the existing byte predictor has no grounded session.

The session uses the existing physical-line role envelopes:

- `CONTEXT:` supplies initial observations before history begins;
- `ENVIRONMENT:` appends later reports to the journal, with automatic report IDs;
- `USER:` carries one whole request;
- `ASSISTANT:` triggers interpretation and prepares the reply;
- `<|endofdialogue|>` clears the episode history and pending choices while
  retaining learned meanings.

History starts at the first environment or user envelope. Subsequent `CONTEXT`
lines are rejected so they cannot alter established knowledge outside the journal.
Generated bytes cannot append observations, execute corrections or reset an
episode. A role marker embedded inside a user line remains ordinary text.

Question recognition uses the learned question interpretation, including questions
without a final question mark. Corrections use learned construction and reference
meanings, including correction wording ending with a question mark. A request
matching both routes withholds instead of choosing a mutating interpretation.
Known ambiguous report references ask for clarification; unknown requests receive
a bounded refusal rather than an unsupported grounded answer.

An ordinary question may interrupt a pending report choice. Numeric clarification
is an explicit protocol, checked against the pending candidates and history/model
revisions. It must also come from the same host-provided source as the original
correction. New observations make an old choice stale. Source identifiers are
trusted host metadata, not identities inferred from words in the message.

The raw-file trainer has one source identity, `trusted_stream` by default, for
reports and corrections. `grounded_source=ID` changes it. A richer host can set
`report_source` and `user_source` before delivering messages; the mixed-dialogue
test exercises multiple sources this way. A raw transcript does not authenticate
real people merely by containing a source-looking name.

## Bootstrap and trainer integration

`python/build_grounded_bundle.py` assembles a path manifest from the existing
teaching files. It expands the old probes' prefix-based initial-world format into
explicit initial observation text. This expansion is outside the runtime; the
loader contains no templates for entities, initial worlds or English meanings.
No held-out examples or answers are read by the bootstrap loader.

`cpp/apps/grounded_bootstrap.h` reconstructs primitive policies from the existing
short demonstrations, observation/question language from the earlier verified QA
corpora, historical references from historical answers, and correction
constructions from consequence answers. All side-effecting training calls use
runtime checks; release builds with `NDEBUG` do not compile training away.
The supplied demonstration bundle currently contains seeds 0, 1 and 2.

The trainer's ordinary byte learning remains enabled in the integration test.
The grounded symbolic models stay frozen while reports and revisions update
episode knowledge. This distinction matters: the test demonstrates coexistence
with byte training, not new language acquisition from that byte stream.

Checkpoint probes receive a deep copy of the grounded reader, journal and pending
interaction. Restoring the original session preserves the training episode,
including partially received messages. This isolation concerns the grounded
session; it does not redesign the older trainer's general sequence-memory probe
behavior. `grounded_state=1` optionally prints the final grounded state for
diagnostics; it is off by default.

The integration test also caught a prompt-framing bug: the generation helper
omitted the carry symbol expected by `run_block`, losing the prompt's first byte.
Dropping an initial newline could prevent an evaluation reset when the copied
reader was midway through a message. The helper now supplies that carry, and
grounded file ingestion also preserves the file's first byte. Probe correctness
is checked at every checkpoint, not only after a completed dialogue.

## Mixed-dialogue validation

The release test uses twelve new-name scenarios containing 47 turns each, with
the same running session retaining models between episodes. Its input supplies
only source identity, generated/external provenance and raw message bytes. No
question/correction category, correct report ID, operation or answer is supplied.
Replies come through the actual Organism byte distribution.

The three seeds use byte chunks of 1, 7 and 113 bytes respectively, while relation
and metadata-field identifiers also vary. Each seed produces:

| Measure | Result |
|---|---:|
| Mixed input turns | 564 |
| User replies independently checked | 408 / 408 |
| Ordinary grounded questions | 216 |
| Correct unknown answers among those questions | 24 |
| Environment reports journaled automatically | 108 |
| Accepted corrections | 60 |
| Report clarification requests | 24 |
| Evaluation clones preserving pending interaction | 12 / 12 |
| Current/historical knowledge snapshots checked | 2,976 |
| Record versions checked | 2,412 |

The scenarios include corrections whose current effect is hidden by a later
event, interrupted clarification, invalid/wrong-source choices, stale choices,
wrong-source corrections, generated role-marker text, late context, lost
visibility, partial evidence, restored complete coverage and episode reset.
Full historical states and record versions are checked after every turn, rather
than scoring answers alone. These are repeated controlled scenarios, not 564
independent language problems.

The standard-trainer smoke test runs a separate raw transcript with learning
enabled, 31-byte blocks and probes every 97 bytes. A second run omits intermediate
probes. Both finish with the same grounded state and counters: three requests,
two questions, one journaled report and one correction. Every checkpoint QA probe
answers its separate fresh-world question correctly. A run with grounding disabled
also completes. This is a short integration test, not a long-run learning result.

## Allocation bug exposed by integration

The first real-trainer attempt crashed with or without grounding enabled.
AddressSanitizer identified an out-of-bounds access in `alloc_unit_in_class`:
128 units contain one motif, but the allocator could select any of six K classes
and use a nonexistent motif cursor. Its modulo wrap also changed classes when
the motif count was not a multiple of the number of classes.

Allocation now returns unavailable for absent classes and wraps each cursor only
among motifs of its own class. A sanitizer test checks populations from one unit
through 1,665 units, including partial motifs and uneven class counts, plus exact
allocation order, fallback and exhaustion. This can change placement in older
uneven-population runs; previous throughput/learning benchmarks have not been
rebaselined here.

## Reproduction and remaining work

Run `bash scripts/grounded_session.sh` under WSL with the preceding grounding
teaching files present. It builds release probes, runs session/allocation sanitizer
contracts, executes three mixed-dialogue seeds, runs the actual trainer with and
without intermediate probes and with grounding disabled, then invokes
`python/check_grounded_session.py`. The auditor independently interprets the raw
dialogue, reconstructs evidence and revisions, checks exact replies and all states,
and records source/input/binary/output hashes in `logs/grounded_session/audit.json`.

Session sanitizer contracts also test overlapping question/correction meanings,
source-bound clarification and deep-copy isolation. No public curriculum files or
builders under `/home/user/curriculum_v2` are modified.

The original experiment did not teach new report, question, reference or correction
meanings from incoming verified feedback; those used a separate teaching phase.
It did not unify the physical-action learner with this runtime, persist/reload
trained memories, support unrestricted grammar, learn source reliability or
replace supplied search/control with a learned policy. Those boundaries remain
part of the broader language-grounding objective.

Follow-up: [verified session teaching](GROUNDED_TEACHING_EXPERIMENT.md) now adds
observation-language acquisition from separate verified feedback in the actual
trainer, while retaining the frozen configuration tested here. The new experiment
also tests learning across episode resets and corrections using new report forms.
Question/reference/correction learning and physical actuation remain separate.
