# Continuing long-task adapter predeclaration

This is a bounded integration preflight, declared before its measurements. It
does not train a scheduling policy. The adapter extends an existing
`GoalControlledRelationalSession` in place: all prior semantic receipts,
procedures, policy weights, policy updates and terminal credit remain. In
particular, the six-edge `parent_route` concept and its language frame remain
available while the nine-edge meaning is learned from twelve final Boolean
concept/language examples. One short-route procedure is then obtained by the
ordinary learned planner's own three-action execution and verified observations.
No definition, program, successful control schedule or preferred derived goal is
installed. All teaching and own-action bootstrap receipts are exported.

The public physical task retains nine necessary route edges and thirty-one
disconnected distractor actions over thirty-two entities. Affordance metadata
describes every action. Limits are declared as 256 decisions, 32 motors, 16
derived candidates, minimum two expanded atoms, preview cap 4,096 and inherited
physical planner cap 32,768. All prices are zero for the separately authorized
success-first objective; raw work remains measured. Capacity sixteen is declared
upfront to admit both retained six-edge and three-edge macro alternatives.

The semantic check evaluates all 512 fresh-binding nine-edge subset worlds and
all 64 six-edge subset worlds. Generic proposals are enumerated with sixteen
capacity and eight order seeds; previews are evaluated independently, including
invalid or exhausted alternatives. The bounded reference smoke uses seeds 0/1,
arrival ticks 8/18, and frozen plus semantic-learning modes with zero policy
updates. The reference is the previously declared public-feature variant 1;
failed cases, costs and global-cap retries will be retained. No training run or
larger sweep is authorized by this preflight declaration.

`LongEnvironment::satisfaction` receives a public request and parses its public
language and arguments, then uses independent graph traversal. It never maps
generated goal IDs to a private desired route. This allows the existing generic
learning harness to supply ordinary outcome callbacks for any proposed supported
frame without changing the continuing seven-action learner.

## Version 2 boundary declaration

The original version 1 source and 8/18-arrival sweep remain fixed under
`logs/goal_long_adapter_v1`. The reusable adapter now rejects arrivals at or
beyond decision twelve: a nine-motor completion plus inspection, activation and
submission can finish at twelve, and the generic mission harness must never
declare success before a future required root arrives. Version 2 therefore uses
arrival ticks 8/10, with the same seeds, limits, reference and semantic conditions.
Extension also requires learning enabled, rejecting frozen learners before any
semantic receipt is applied. Direct checks cover both boundaries and independently
verify all nine edges remain necessary amid every distractor action. This is an
adapter contract correction, not a control-policy improvement.

## Actual warmed-state declaration

The fresh-fixture results must not substitute for the actual continuing learner:
the protocol warm-up accumulated its own six-edge executions. A separate bounded
variant reconstructs the exact previously measured warm100 checkpoint using the
unchanged pilot routines and compares every exported float weight with that
checkpoint, requiring 12,800 updates and 100 mission credits. This is replay of
the existing warm history, not another curriculum. Existing pending semantic
receipts are rebuilt if needed, then the same live learner receives the twelve
raw long examples and one own short-route execution. The helper must preserve
its policy and credit, six-edge meaning, and prior execution evidence.

After extension, eight independent clones of that same warmed state run the
declared evaluator reference at task-order seeds 0/1, arrivals 8/10 and both
semantic modes, with zero further policy updates. Warm policy RNG/order state is
retained: these are task-order variants, not eight independent trained learners.
The same 512 long and 64 retained subset checks, complete generic proposal
inventory and preview failures are exported. No additional procedure teaching,
private candidate filtering, policy optimization or budget changes are permitted
within this variant.

## Measured adapter results

The retained library acquires one exact nine-edge meaning with local expression
`parent_route(0,2), short_route(2,1)` (108,301 induction work, 435 candidates).
The long probes pass 512/512 and the old six-edge probes pass 64/64. Generic
enumeration finds 52 source instances and twelve qualifying macros, all retained
under capacity sixteen in eight of eight tested orders. Seven three-edge
candidates give valid progress, one gives valid zero progress, and four six-edge
candidates exhaust their 4,096-prediction preview. No candidate is filtered by
private usefulness.

The final version 2 fresh-semantic-only smoke succeeds in four of four frozen
references and two of four semantic-learning references. The failed task-order
1 cases at arrivals 8/10 exhaust 256 decisions with one/two motors, respectively;
they repeat the global-cap search 231/229 times. Every urgent query succeeds.
The older version 1 8/18-arrival artifact remains preserved separately.

The actual warm100 checkpoint reconstructs exactly: all saved float weights,
12,800 policy updates and 100 credit receipts match. Its semantic cache is dirty
at that boundary. Rebuilding the existing receipts reveals zero reusable
procedures, despite the 93 successful physical roots during warming. The adapter
then adds one procedure from its declared own three-action execution. No old
concept, language, transition or execution evidence is discarded.

The actual-warm reference succeeds in four of four frozen cases and two of four
semantic-learning cases. Both task-order 0 semantic failures (arrivals 8/10)
stop at 256 decisions with three motors and 222 global-cap retries. Task-order 1
semantic cases succeed in 94 decisions and nine motors. All eight cases contain
an actual unfinished-work interruption and answer the urgent query correctly.
This identifies a reference/protocol observation limitation on the actual
continuing state; it is neither a new policy acquisition score nor a reason to
delete the six-edge library. ASan/UBSan passed the separate semantic, proposal and
adapter-boundary smoke. Evidence, hashes and per-case counters are recorded in
`GOAL_LONG_ADAPTER_VALIDATION.json`.

## Failure atomicity

The reusable extension helper now stages its evidence log and snapshots the
complete existing knowledge state. Successful teaching occurs on that same live
session. Any exception restores the exact prior snapshot; policy weights and
credit are never modified. Prior concept, language, transition and execution
receipts are compared field by field on success. A focused regression forces a
language-capacity failure after concept updates and two language receipts have
already been applied, then checks receipt/model equality, a live pending token,
its verified feedback and the next exploratory action/token stream. This fix is
separately validated; earlier successful and failed feasibility artifacts remain
immutable.

## Paid-exhaustion observation variant declaration

After the actual-warm negative, a separate opt-in protocol flag exposes whether
the current cached search actually exhausted its last paid global planner
allowance. With `agenda_search_exhaustion` enabled, agenda observation 15 carries
that bit, replacing a redundant parent/derived flag; the default observation
contract remains unchanged. The new evaluator-reference rule skips a derived
candidate only when both its current search-budget flag and that new paid-global
exhaustion bit are true. It keeps the previous retry behavior at smaller paid
allowances. There is no private usefulness input or task-specific candidate
filter. This variant will run only after the protocol owner's focused validation
freezes the core and preview metadata.

The separately recorded actual-warm variant reconstructs and checks the same
saved warm100 checkpoint, applies the same raw extension in place, and uses the
same eight task-order/arrival/semantic cases, sixteen-candidate capacity,
256/32 decision/motor bounds and zero-price objective. Old feature/reference
variants and their failures remain immutable. This is an evaluator-feasibility
observation change, not evidence that the neural control policy learned it.

The measured opt-in variant passes all eight references: four frozen and four
with semantic learning. All eight are actual unfinished-work interruptions and
answer the urgent query on time; every completed root uses exactly nine motors.
The frozen cases are unchanged at 143/157 decisions. The two previously stalled
semantic cases now complete in 115 decisions after two genuine paid global-cap
exhaustions each; the other two semantic cases complete in 94 decisions. The
reference skips those exhausted alternatives and continues using the retained
library. Limits and prices are unchanged, all raw preview/proposal/prediction
counters remain recorded, and no post-warm policy updates occur.

Authoritative artifacts are under `logs/goal_long_warm_adapter_v2`: `config.json`
was written before execution, `source`/`source_manifest.json` freeze the tested
implementation, and `warm_summary.json` plus `warm_trace.jsonl` retain outcomes,
full public observations, actual motor callbacks and paid planner allowances.
The trace's computation rows include the public input scenes and affordances,
current model versions and exact paid allowance rather than merely the requested
global limit. This is one reconstructed warm learner, two task-order variants
and two arrival times per semantic condition; it is not a multi-seed policy
acquisition or structural-transfer experiment.
